Module 1

Overview & Architecture of Dashboard 2.0

The executive and analytical workspace inside Oracle Profitability and Cost Management Cloud (PCMCS) for evaluating KPIs, cost allocation flows, and multi-dimensional margin calculations.

Section 1 of 7

Executive Overview

Dashboard 2.0 is Oracle's next-generation visualization framework for PCMCS, offering ultra-responsive rendering, dynamic cross-filtering, and real-time integration with underlying Essbase cubes and Forms 2.0 grids.

A single Dashboard 2.0 layout can hold up to 12 components — interactive charts, financial forms, tile callouts, and web links. Hovering over any component in design or runtime mode reveals its contextual Dashboard Component Toolbar in the upper-right corner.

Canvas capacity Dashboard 2.0 supports up to 12 active components on a single canvas. Each component is dynamically bound to an underlying PCMCS form or cube analysis view.

Strategic Business Purpose

Dashboard components turn static financial statements into dynamic analytical tools:

Executive Trend Tracking

C-suite leaders and business unit managers instantly evaluate profitability by region, product line, or channel.

Interactive Root-Cause Drill-Down

Hover over an anomaly in a chart and drill directly into the underlying form grid without leaving the workspace.

Dynamic Simulation & Rule Execution

Business rules, allocation calculations, and Smart Push operations trigger directly from component toolbars.

Technical Architecture & Data Flow

Every dashboard component is a specialized visualization viewport over an underlying Forms 2.0 grid or direct Essbase cube POV.

Architectural layerTechnical componentOperational role
VisualizationDashboard 2.0 Component (Chart / Tile / Grid)Renders visual charts (up to 10,000 cell data points) or tabular views with hover toolbar controls.
Form DataForms 2.0 Grid / Analysis ViewDefines dimension layouts, suppression rules, member selectors, and local POV.
Calculation EnginePCMCS Calculation Rules & Smart PushExecutes allocation scripts, cost drivers, and transfers data across cubes.
DatabaseEssbase Multi-Dimensional CubeStores underlying intersections, historical rates, allocated pools, and transactional figures.
10,000-cell rendering limit Dashboard 2.0 components enforce a maximum rendering threshold of 10,000 data cells per chart. Larger forms (e.g. 200 rows × 100 columns) must be filtered using local POVs or suppressed intersections.

Module 3

Configuration & Implementation Workflow

The end-to-end steps for building a component and the closed analytics-to-allocation loop that makes Dashboard 2.0 powerful.

Section 3 of 7

Step-by-Step Component Configuration

StepAction
1Add Component Placeholder — click the Add Component (+) icon on the main designer toolbar to create a workspace tile.
2Select Visualization Type — drag a chart type (Bar, Line, Pie, Tile, Gauge, Bubble) from the Library panel into the placeholder.
3Bind Data Source & Form — in the Properties panel's Chart tab, select the target Data Source form and underlying Essbase cube.
4Configure POVs & Filters — set Global or Local POV filters (Period, Year, Scenario, Version, Entity) to keep intersections under 10,000 cells.
5Attach Rules & Instructions (optional) — add operational instructions (up to 2,000 characters) under General; link allocation rules under Associations.
6Save & Preview — click Actions → Save and Run to finalize design and enter Runtime mode.

End-to-End Analytics & Allocation Loop

How executive summary visualizations bridge directly to rule execution:

1. Executive views dashboard→ 2. Identifies cost anomaly→ 3. Actions → Analyze→ 4. Ad-hoc cell drill-down
5. Actions → Open Form→ 6. Adjust driver value→ 7. Save & run allocation→ 8. Refresh dashboard
Module 4 · Applied scenario

Bikes Corp Performance Analysis

Bikes Corp manufactures six bicycle models (BB100, BB200, BB300, SR100, SR200, SR300). The CFO noticed margin compression on the flagship line and requested a profitability audit using the PCMCS dashboard.

Section 4 of 7
Phase 1Bubble Chart Audit
Phase 2Trend Drill-Down
Phase 3Root-Cause Investigation
Phase 4Resolution & Re-Allocation

Phase 1 — Multi-Dimensional Bubble Chart Audit

The Finance Manager reviews the Performance Analysis Bubble Chart on the dashboard:

  • X-Axis (Sales Revenue): ranges up to $5.0M
  • Y-Axis (Profit Margin %): ranges from 0% to 35%
  • Bubble Size (Total Cost Pool): combined manufacturing, freight, and overhead allocations
Observation Model BB100 shows the largest bubble with high revenue ($4.5M) and a 25% gross margin — but its oversized bubble signals disproportionately high cost allocations compared to model SR100.

Phase 2 — Monthly Profit Trend Drill-Down

The manager examines the Profit Trend Analysis line chart (January–June):

  • From January through May, BB100 generated consistent monthly profits of ~$18M revenue.
  • In June, BB100 profit plunged sharply toward zero (~$0.5M) despite identical sales volume to May.

Phase 3 — Root-Cause Investigation via Toolbar Actions

The manager hovers over the BB100 June data point and selects Actions → Analyze. PCMCS instantly opens a dynamic ad-hoc form detailing the line items:

MonthRevenueManufacturing CostFreightMarketing AllocationNet Profit
May$18.0M$10.0M$2.0M$3.0M$3.0M
June$18.0M$17.0M$3.0M$2.0M$0.5M
Root cause uncovered Raw material allocations spiked from $10M to $17M in June due to an incorrect cost driver rule assignment in the manufacturing allocation pool.

Phase 4 — Resolution & Re-Allocation

  1. From the component menu, the manager selects Actions → Open Form to open the Manufacturing Allocation Form.
  2. Corrects the allocation driver percentage for raw material overhead.
  3. Clicks Save to commit new values and execute the allocation business rule.
  4. Returns to the dashboard and clicks Refresh on the component toolbar.
Outcome June profit for BB100 rebounds to expected levels ($2.8M); the bubble size shrinks proportionally, and executive financial reporting is restored to accuracy.

Module 5

Governance, Best Practices & Troubleshooting

Enterprise standards for keeping dashboards fast, accurate, and maintainable.

Section 5 of 7

Enterprise Best Practices

Enforce the 12-component rule Keep dashboards focused — restrict canvas layouts to 4–6 key components for optimal executive readability and fast rendering.
Optimize dimension POVs Place static dimensions (Year, Scenario) in the Global POV bar and dynamic dimensions (Product, Region) in Local POVs to minimize query overhead on Essbase.
Configure missing value display By default, charts plot suppressed/missing values as zero. Set Plot Missing Values as Zero = No to eliminate erroneous drop-offs in trend charts.

Common Implementation Pitfalls

PitfallRoot causeCorrective action
Confusing Save vs. Save and RunUser clicks component Save expecting the layout to persist.Use component Save for data edits; use Actions → Save and Run for layout changes.
Blank chart renderingUnderlying form exceeds the 10,000-cell limit.Apply member suppression or restrict row/column dimensions in the form designer.
Missing "Analyze" optionComponent built on an ad-hoc query or URL, not a Forms 2.0 grid.Rebuild the component using a saved Forms 2.0 grid as its data source.

Troubleshooting Guide

SymptomDiagnostic stepResolution
Data changes don't reflect on dashboardCheck if the Essbase cache/dashboard view was reloaded.Click Refresh on the component toolbar to re-query the cube.
Edit Form / Create Form disabledVerify user Role Access in Access Control / EPM Security.Assign Service Administrator or Power User (Designer) role.
Unexpected zero spikes in line/area chartsCheck chart display properties for empty-cell treatment.Set Chart Type → Object Display → Plot Missing Values as Zero = No.
Allocations fail to executeCheck Job Console logs.Click Actions → Open Jobs to review execution error messages.
