Query Design for Reports

Reports use saved queries from the Intelligence area. Queries must follow specific dimension rules: ≥1 Row Dimension, ≥1 Column Dimension, Exactly 1 POV (Point of View) Dimension.

Query Requirements for Reports:
✓ At least 1 dimension on Rows (e.g., Product, Department, Region)
✓ At least 1 dimension on Columns (e.g., Revenue, Cost, Profit)
✓ Exactly 1 dimension on POV — global filter/slicer (e.g., Period: Jan-2024)
✗ Multiple POV dimensions will fail report generation

Common Query Mistakes

❌ Multiple POV Dimensions: Using both "Period" and "Scenario" on POV will cause report failure. Use exactly ONE.
❌ No Row or Column Dimensions: Reports require at least one row and one column. Empty queries will fail.
❌ Stale Query Configuration: Always refresh query definitions in UI before running reports. Cached definitions can cause "No Data" results.

Best Practices & Production Readiness

Key recommendations for professional report deployment and user adoption.

1️⃣ Meaningful Naming Convention

Always provide clear, descriptive report names and detailed descriptions. Examples: "Quarterly P&L by Division", "Monthly Margin Analysis by Product Line", "Executive Profitability Review".

2️⃣ Verify Queries Before Linking

Validate underlying queries in Smart View or Query Builder prior to linking to reports. Ensure they return expected data and follow dimension rules (≥1 row, ≥1 col, exactly 1 POV).

3️⃣ Enforce One POV Dimension

Strictly ensure queries have exactly one dimension on the POV. Multiple POVs will cause report execution to fail with "Invalid Query" errors.

4️⃣ Optimize for Reporting During Calculation

Pre-aggregate Essbase blocks during model calculation with "Optimize for Reporting" flag. This dramatically speeds up query and report retrieval times, especially for large datasets.

5️⃣ Use Financial Reporting Web Studio for Formatting

PCMCS Reports provides basic tabular output. For production reports with logos, custom headers, charts, conditional formatting, use Financial Reporting Web Studio. It integrates seamlessly with PCMCS data.

6️⃣ Grant Proper Permissions

Mistake to avoid: Forgetting to grant Execute permissions or Data Grants to Viewers/Users. They won't see or run reports without proper authorization.
Solution: Assign "Run" permission on report/folder and configure Data Grants limiting which data they can access.

7️⃣ Distribute via PDF, Not Direct Access

Export reports as PDF for email distribution and archival. Users who cannot access PCMCS directly can still view formatted results. PDF is also better for audit compliance.

8️⃣ Document Report Purpose

Always document the business purpose, audience, and expected use of each report. This helps future users and reduces duplicate report creation.

❌ Common Mistakes to Avoid

Mistake #1: Relying on unformatted output
PCMCS Reports produces raw query output as tables. Don't expect polished, production-ready PDFs. Use Financial Reporting Web Studio for formatted documents.
Mistake #2: Not granting permissions
Creating a report doesn't automatically let users run it. Forgetting to grant Execute permissions and Data Grants leaves users unable to access reports.
Mistake #3: Using incorrect query design
Queries with multiple POV dimensions, missing row/column, or unvalidated data will fail silently. Always test queries in Smart View before linking to reports.
Mistake #4: Stale data in reports
Running reports without recalculating model data or refreshing report definitions produces outdated results. Always recalc before running critical reports.

✓ Correct! Without Execute permissions, users simply cannot see or access the report. Proper security is enforced at the repository level.

✓ Correct! The POV is a critical filter that sets the data context. Only ONE POV is allowed per report query.

✓ Correct! This follows the required structure: row dimension (Product), multiple column dimensions (financials), and exactly one POV filter.
